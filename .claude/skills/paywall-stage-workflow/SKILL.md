# Цикл этапа

Этапы: 0 превью концептов, 1 каркас, 2 Figma-макет, 3 верстка, 4 backend и БД, 5 деплой, 6 README и финал.
Источник правды по состоянию: `.claude/project-state.md`.

## Порядок
1. **Старт этапа.** Прочитай `CLAUDE.md` и `.claude/project-state.md`. Назови этап и что в него входит.
2. **Реализация.** Только объём этого этапа. Расхождение с планом выноси пользователю, не расширяй молча.
3. **Проверка.** `npm run check` и `npm run build`. Всё зелёное, иначе чини.
4. **Ревью.** Пройди скилл `paywall-review` целиком, включая diff и UI, и почини найденное.
5. **Журнал.** Обнови `.claude/project-state.md`: что сделано, что проверено, что осталось, какие решения
   приняты. Если менялась архитектура, роуты или команды, обнови `CLAUDE.md`.
6. **Стоп.** Покажи пользователю: что сделано, как проверено, как посмотреть (команда или ссылка),
   открытые вопросы. Дальше ничего не делай.
7. **После явного ОК:** `git add` только файлов этапа, один коммит с понятным сообщением, `git push origin main`.
   Сообщение коммита заканчивай строкой атрибуции, которую задаёт среда.
8. **Следующий этап.** Предупреди пользователя одной строкой, какой этап начинаешь, и переходи к шагу 1.

## Правила
- Без ОК пользователя не коммитить и не пушить.
- Не коммитить `.env`, `node_modules`, `.output`, `.nuxt`, `.vercel`.
- Не использовать `--no-verify`, `--force` и перезапись истории без прямой просьбы.
- Логины в Vercel, Figma и GitHub делает пользователь. Токены и пароли в чат не просим.
- После добавления или изменения скиллов и плагинов напомни пользователю выполнить `/reload-plugins`.
