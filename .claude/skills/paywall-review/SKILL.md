# Ревью этапа paywall

Цель: найти то, что пропустили автопроверки. Не доверяй собственному резюме «что сделано»: читай изменения.

## Обязательные команды (всегда, до остального)
```bash
npm run lint         # eslint
npm run lint:style   # stylelint по app/**/*.{vue,scss}
npm run typecheck    # nuxt typecheck (vue-tsc)
npm run build        # сборка должна проходить
```
Любая ошибка блокирует этап. Не отключай правила, чтобы пройти проверку: чини причину.

## Шаги
1. **Прочитай diff целиком** (`git diff` и `git status`, новые файлы читай полностью). Если изменений
   больше 500 строк, предложи разбить этап.
2. **Сформулируй своими словами, что и почему изменено**, и сверь с реальным diff. Расхождение значит,
   что решение либо не то, либо не понято.
3. **Линтер, stylelint, vue-tsc, build** (блок выше).
4. **Руками, не только автотестами**: запусти `npm run dev` и проверь 1-2 сценария. Для API: `curl`
   на `/api/offers` и `/api/purchase`.
5. **Граничные и плохие входные данные**: пустой `offerId`, неизвестный `offerId`, нет `deviceId`,
   пустое тело, неверный метод, повторная отправка одного запроса, обрыв соединения.
6. **Доступ и деньги**: повторный `POST /api/purchase` с тем же `Idempotency-Key` не создаёт вторую
   запись; чужой или выдуманный `deviceId` не даёт доступа к чужим данным; ответы не раскрывают
   строку подключения и стек.
7. **Лишнее**: новые зависимости, абстракции и «универсальные» решения для случаев, которых нет в
   задании. Нет убедительной причины, вырезай.
8. **Консистентность**: нейминг, структура файлов, обработка ошибок, БЭМ и токены совпадают с
   остальным кодом и с `CLAUDE.md`.
9. **UI-сверка** (этапы 3 и выше): скриншоты на 360, 390 и 430px против Figma; отступы, радиусы,
   шрифты, размеры нажатия не меньше 44px, состояния loading, error, success, видимый focus.
10. **Второй проход с чистого листа** для критичного кода (покупка, БД): перечитай diff, не вспоминая
    контекст, и ответь на вопрос «что здесь может сломаться».
11. **Коммитить только то, что можешь объяснить**. Непонятный кусок перепиши или удали.

## Дополнительные инструменты
- `/code-review` и `/simplify` на локальный diff; `/security-review` для серверных роутов.
- Агенты `pr-review-toolkit:silent-failure-hunter` (try/catch, фолбэки) и `pr-review-toolkit:code-reviewer`.

## Формат отчёта пользователю
Коротко: что проверено и чем, что найдено и починено, что осталось рискованным. Затем стоп: коммит и
пуш только после явного «ОК» пользователя.
